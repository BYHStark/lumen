# 审查清单

先找会在生产里造成错账、重复投递、租户串数据、进程停不下来的问题。风格问题放后面。

按这个顺序看，停在第一个实质问题，把它讲清楚：

1. 这个改动属于 `docs/progress.md` 的当前阶段吗？超前的依赖或框架要退回。
2. 失败路径有测试吗？只有成功路径不算过关。
3. 可重试的写有幂等键吗？用量和关账会不会因为重试而重复？
4. 查询和写入有租户约束吗？租户 A 能否读到租户 B？
5. 每个出站调用有从请求或任务派生的 context 和超时吗？
6. 每个新 goroutine 谁启动，谁负责退出？关闭时会不会继续领取？
7. error 是包装后返回，还是被丢掉或只打日志？
8. 金额、状态和时间的类型对吗？有没有 `float64` 金额或依赖服务器本地时区？
9. 没有测量证据时，有没有性能改动或 `sync.Pool`？

反馈格式：

- 问题：一句说清会坏什么。
- 证据：文件、测试或缺失的测试。
- 知识点：这次具体在练什么。
- 下一小步：用户自己要写的失败测试或修改，不附完整实现，除非他已经要求答案。
